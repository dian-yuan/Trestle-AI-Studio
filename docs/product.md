# 产品说明

> 本文描述 Trestle 解决什么问题、适合谁，以及本仓库与专业版的边界。
> 不展开内部创作规则和字段契约。

---

## 1. 一句话

Trestle 是一个**本地优先的 AI 视频工程工作台**：把剧本、场、分镜、提示词和资产
放在一个工程目录里，用本地工作台读写、审片、布线，最后交给 LibTV 出片。

## 2. 解决什么问题

AI 视频制作的难点通常不在"生成一个镜头"，而在：

- 一个片子里几十个镜头，角色、场景、道具要一致；
- 剧本、分镜、提示词、参考图散落在聊天记录和文件夹里；
- 生成要花积分，不能反复试错；
- 成片、字幕、封面、交付包要能追溯。

Trestle 把这些收进一个**工程目录**，让文件成为唯一事实源，工作台负责读写、
检查、布线、同步和交付。

## 3. 适合谁

- 做 AI 短剧、广告、产品片、概念片、讲解视频的创作者；
- 需要多人协作、需要交付包和版本追溯的小团队；
- 想把 AI 视频流程工程化，而不是每次从聊天窗口重新开始的人。

不适合：

- 只想生成一张图或一个镜头的人；
- 不需要工程管理和交付追溯的纯尝鲜用户。

## 4. 能力范围

| 阶段 | 能力 |
|---|---|
| 创意 | 导演简报、创意库、项目结构 |
| 剧本 | 内容大纲、分场剧本、台词 |
| 资产 | 角色、场景、道具、风格、品牌资产 |
| 分镜 | 场、分镜、镜头、关键帧 |
| 提示词 | 静帧 / 运动提示词、负向词 |
| 布线 | 本地图谱、LibTV 节点 / 分组映射 |
| 审片 | 镜头状态、审阅记录、返修 |
| 交付 | 成片、字幕、封面、交付包 |

工作台本身**不生成图片或视频**。生成由用户在 LibTV 点击，避免误花积分；
工作台负责建节点、挂参考、记录映射、同步结果。

## 6. 本地优先与隐私

- 工程文件保存在本地，不上传；
- 工作台只绑定 `127.0.0.1`；
- 不包含遥测；
- 诊断信息只包含版本、系统、依赖状态，不包含剧本、提示词、素材或 token；
- LibTV 授权由用户自己的账号完成。

## 7. 平台与依赖

- Windows 桌面应用；
- 需要 WorkBuddy 或 Claude Code 作为 Agent；
- 需要 LibTV 账号；
- 需要 FFmpeg（官方安装包内置）。
